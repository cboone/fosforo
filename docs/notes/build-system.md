# The build system

How `build.zig` and `cmake/` actually behave, and the parts of the toolchain that are restated by hand because nothing generates them. Read this before editing `build.zig`, anything under `cmake/`, `macos/Info.plist`, or any identifier a host stores.

- **`xcrun` caches tool lookups.** If `xcrun metal` reports the Metal toolchain missing right after installing it, run `xcrun --kill-cache`.

- **CLAP bindings come from preprocessed headers.** Zig 0.16's `translate-c` mishandles `#pragma once` under path aliasing, so `build.zig` runs the headers through `zig cc -E` first. Object-like macros do not survive that; the ones that matter are restated and tested in `src/clap/c.zig` (ADR 0004). **Do not `refAllDecls` the translated module.** `translate-c` leaves `@compileError` stubs for declarations it could not translate, eight of them here, and referencing one detonates it: the sweep fails on `__nonnull` from `<builtin>`, a compiler attribute with nothing to do with CLAP, so the error reads as this project's bug. `src/clap/c.zig`'s own sweep therefore covers that file's declarations and `feature`, and reaches `c` only as a value, which does not descend (#95).

- **`unnamed_0` is toolchain-generated.** The anonymous union in `clap_window` is reached only through `clap.cocoaView()`. Re-verify after any Zig upgrade.

- **Metal's and AppKit's constants are hand-restated.** Their headers are Objective-C, so `translate-c` cannot read them the way it reads CLAP's. `MTLPixelFormat`, `MTLLoadAction`, `MTLStoreAction`, and `MTLPrimitiveType` live in `src/gpu/metal/renderer.zig`, and #60 added two of the first — `BGRA8Unorm_sRGB` at 81 and `RGBA32Float` at 125, both read out of `MTLPixelFormat.h` rather than recalled, which is the practice that caught the line-strip enum; `NSView.autoresizingMask` lives in `src/platform/objc.zig`. Unlike the restated CLAP macros in `src/clap/c.zig`, there is no surviving header symbol to test them against. They are ABI values Apple cannot renumber, and a wrong one shows as a black or garbled drawable rather than as anything subtle. **The two `NSView.autoresizingMask` values now have a pin anyway** ([#97](https://github.com/cboone/fosforo/issues/97)), on `c.zig:69`'s precedent and with its disclaimer: it restates 2, 16 and their OR a second time and catches a one-sided edit, which is all a restatement can do without a symbol to compare against. The pair is asserted separately as well as combined, because the OR alone reads 18 either way and cannot see the two swapped. The Metal constants have no equivalent, for the reason the sentence before this one gives: a wrong pixel format is loud, while a transposed autoresizing mask silently breaks a resize and nothing else here would say so.

- **`@embedFile` reaches `shaders/` through the import table.** It resolves relative to the importing file and cannot escape the module root, which is `src/`. `build.zig` adds the shader with `addAnonymousImport`, which is why `@embedFile("scope.metal")` works from `src/gpu/metal/`. Keeping shaders outside `src/` is deliberate: `zig build validate-shaders` treats that directory as shaders rather than as Zig.

- **Keep four deployment targets in step:** `build.zig`, `cmake/CMakeLists.txt`, `macos/Info.plist` and `packaging/distribution.xml` all specify macOS 11.0. The fourth is the one that gets missed, and it fails in the opposite direction from the other three: it is the installer's `allowed-os-versions`, so raising the floor in the three that build a binary and not in the one that gates installation leaves the package accepting a machine the binaries will not run on. Nothing checks any of the four against another.

- **The version lives in five places and `scripts/build-installer` checks four of them.** `build.zig.zon`'s `.version`, `CFBundleShortVersionString` and `CFBundleVersion` in `macos/Info.plist`, and `project(fosforo VERSION ...)` in `cmake/CMakeLists.txt` — that last one reaches the shipped Audio Unit's own plist through clap-wrapper's `BUNDLE_VERSION`, and it went unchecked until it was found during a drift sweep, so bumping the first three for a release and forgetting CMake used to package a component whose plist disagreed with the installer around it and say nothing. `package.json`'s is the fifth and is inert: nothing publishes it. **The check is a refusal and it was planted both ways** — CMake ahead of the rest, and the real release shape with the rest ahead of CMake — and `scripts/build-installer --unsigned` refuses each, naming the disagreeing value.

- **`build.zig` runs `git` at configure time, and three things about that are easy to get wrong.** It stamps the branch and commit into every binary (ADR 0018), and none of the following is stylistic. **`git rev-parse --abbrev-ref HEAD --short HEAD` prints the branch name twice**, because `--abbrev-ref` is sticky across every ref that follows it, so a combined call silently puts the branch in the field meant for the commit and produces a line that is wrong while still looking well-formed; use two calls. **Failure is a supported state, not an error**: `b.runAllowFail` with `.ignore` on stderr, never `b.run`, because `b.run` calls `process.fatal` and a tarball built from `build.zig.zon`'s `.paths` carries no `.git` at all, which must yield `branch=unknown` and a clean build. And **this costs ADR 0009 nothing**, on a stronger precedent than `/usr/bin/codesign`: `b.dependency("objc", ...)` already runs zig-objc's build function at configure time, which executes `xcrun` to find the SDK that nothing here can link Cocoa or Metal without, so a subprocess and a working Xcode or CLT install were both hard requirements before this existed. Where `xcrun` failing is fatal, `git` failing is not. The cost that is real: the option values feed the module's cache key, so the first build after each commit is a full rebuild.

- **The AUv2 build rewrites its own `Info.plist`.** Two `POST_BUILD` scripts correct what clap-wrapper generates, and the `clap-wrapper` CI job asserts both results independently, because a rewriting step cannot detect its own absence. `cmake/narrow-au-resource-usage` strips a hardcoded `resourceUsage` dictionary claiming network and whole-filesystem access, emitted next to the `sandboxSafe` flag that Apple documents as mutually exclusive with it; it no-ops safely if clap-wrapper stops emitting it, so re-check when the pin moves. `cmake/set-au-display-name` replaces the generated name and description, for the reason in the display name bullet below. Both must stay ahead of the signing command, which is the third and last `POST_BUILD` command on that target; see the next bullet for why the order is load-bearing.

- **`cmake --build` no longer touches `zig-out`, and the optimize-mode split it caused is still there.** Two facts that used to travel together and now do not. `cmake/CMakeLists.txt` drives Zig itself, through an `ALL` custom target, because the only thing CMake wants from Zig is `libfosforo_impl.a`. That target used to run a bare `zig build --release=fast`, which also reassembled the Zig-built bundle and signed it ad-hoc, since it passes no `-Dcodesign-identity`: a CMake build silently replaced whatever `zig build -Dcodesign-identity=` had produced, and every check afterwards read a different file than the one that was signed. It now runs `zig build --release=fast --prefix build/zig impl`, and **both halves of that are load-bearing.** The `impl` step assembles no bundle and signs nothing; the prefix keeps its ReleaseFast archive out of `zig-out/lib`, where it would otherwise race a Debug one from any concurrent `zig build`. Measured rather than assumed: the CLAP's hash _and_ its mtime are unchanged across a full `cmake --build`, and `codesign --verify` passes afterwards. The ordering in `scripts/build-release-bundles` is consequently no longer load-bearing, and is kept only because reversing it buys nothing. What survives unchanged is the optimize-mode disagreement: `standardOptimizeOption` declares no default, so a plain `zig build` is **Debug** while everything CMake triggers is **ReleaseFast**, and after `zig build install-plugins` the installed CLAP is Debug next to a ReleaseFast Audio Unit. That is right for local work, since Debug is what emits the render meter REAPER can show and Logic can show nothing under any mode, and wrong for a release: a shipped CLAP must be built `--release=fast` explicitly, which is what `scripts/build-release-bundles` does.

- **The display name lives in four places.** It cannot be derived from one source, because it crosses Zig, CMake, and a generated plist. `src/clap/plugin.zig` holds the CLAP descriptor's `name` and `description` and is the source of truth; `macos/Info.plist` carries `CFBundleName` and `CFBundleDisplayName` for the Zig-built bundle; `DISPLAY_NAME` in `cmake/CMakeLists.txt` covers the CLAP that CMake builds; and `cmake/set-au-display-name` covers the Audio Unit, whose plist clap-wrapper composes from the ASCII `OUTPUT_NAME` and then describes as a wrapper. Change one, change all four. The ASCII `Fosforo` that names files, binaries, and `CFBundleExecutable` is a separate string and must not follow.

- **Some identifiers are permanent.** The AU triple (`aufx`/`Fsfr`/`Ctmn`) and the CLAP plugin `id` are stored in users' project files; changing either makes the plugin read as missing. The manufacturer name and display name are free metadata. See the plan's identifiers section before touching any of them.

- **`--target fosforo_auv2` does not build the CLAP.** Setting `AUV2_MANUFACTURER_CODE` sends `make_clapfirst_plugins` down its explicit-configuration branch, which never adds a dependency from the AUv2 target to the CLAP one. Build `fosforo_all` when both artifacts are wanted. `scripts/build-audio-unit` encodes that, along with configuring only when `build/` is absent, and it is what both `zig build audio-unit` and the `clap-wrapper` CI job run, so the rule cannot be true in only one of the two places.
